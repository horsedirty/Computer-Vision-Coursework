# 从 17 篇论文到结课报告：章节级写作向导

> 前两份文档分别梳理了研究脉络（从哪来到哪去）和技术选型（用谁做什么）。这份文档试着回答最后一个问题：这些材料怎么变成一份像样的结课报告。不是帮你写，是告诉你每一节该放什么、从哪篇论文里拿证据、用什么口吻，以及哪里容易踩坑。

---

## 报告整体结构建议

标准 CV 课程报告的骨架：

```
摘要（Abstract）
1. 引言（Introduction）
2. 相关工作（Related Work）
3. 方法（Methodology）
4. 实验（Experiments）
5. 结论与展望（Conclusion）
参考文献
```

其中第 3 和第 4 节是得分重心。60% 的抗抖动效果靠实验数据说话，40% 的算法效率靠方法设计 + 运行时统计说话。

---

## 摘要（Abstract）

**篇幅：** 150-250 字，一段。

**必须包含的四件事（缺一个就是不合格的摘要）：**

1. **问题是什么**：手持拍摄产生的画面抖动与运动模糊，现有方法在哪方面有不足（批处理、需成对数据、无法区分抖动与物体运动）。
2. **方法是什么**：模块化三阶段流水线（运动估计→运动分解与平滑→帧合成去模糊），核心创新是什么（相对坐标平滑 / 多检测器协作 / SO(3) 建模，选你实际做到了的那个写）。
3. **关键结果**：先空着，做完实验回来填。几句话概括数值结果（比 baseline 提升多少）。
4. **意义是什么**：在线处理、无监督、区分抖动与运动，这三点里挑一个作为核心贡献。

**写作口吻：** 冷静陈述，不夸张。不要出现"本文首次""达到了惊人的效果"这种句式。用"本文提出""在 X 标准数据集上达到 Y 指标"。

**可引用的论文（给摘要定调的）：** LightStab（14）的无监督化思路、GoPro 数据集（07）的问题定义。

## 1. 引言（Introduction）

**篇幅：** 2-3 页，四段。

**第一段：问题定义。** 以手持拍摄的抖动和运动模糊作为开场。不要一上来就甩论文——用一个具体场景建立直觉：比如手机边走边拍，回放时画面抖得厉害且模糊，这是因为什么物理原因（曝光时间内相机位移导致多帧累加；帧间运动不规则导致画面抖动）。

**第二段：现有方法简述 + 缺口。** 两句话概括现有方法的主流路线（端到端 CNN/Transformer、基于光流、基于关键点），然后指出有哪些没解决好的：成对数据获取困难、批处理导致延迟、抖动物体运动难以区分。这里轻引 2-3 篇代表性论文（07 的端到端范式、06 的盲估计局限、10 的光流依赖）。

**第三段：本文方法概述。** 用一段文字描述你的系统架构（三阶段流水线），每阶段一句话说清楚做什么、为什么这么做。画一张流程图（draw.io 画的，别用 AI 生成图），放这里。

**第四段：贡献总结和论文结构。** "本文的主要贡献如下：（1）...（2）...（3）..." 然后 "本文后续章节安排如下：第二节...第三节..."

**可引用的论文：** 07（GoPro 问题定义）、06/10（现有方法局限）、14（整体架构思想来源）、17（相对坐标平滑创新点）。

## 2. 相关工作（Related Work）

**篇幅：** 3-4 页。这是最能展示你读了论文的部分。

**使用「00_研究脉络」文档中的三层叙事框架，直接填充。** 不要逐篇论文罗列，要讲故事。每一层对应 1-1.5 页。

**第一层：基础范式（2017-2020）。**
- 去模糊的端到端范式：07 的 GoPro 数据集 + 邻帧堆叠 CNN
- 防抖的深度学习化：10 的光流路径 vs 06 的盲估计路径
- 在线处理：11 的多网格 warping 面向在线
- 要点：不是复述每篇论文的细节，而是解释为什么这些早期工作奠定了什么基础，又留下了什么问题。

**第二层：融合机制升级（2021-2023）。**
- 注意力：12 的门控时空注意力改变了跨帧融合的范式（从被动到主动选择）
- 多任务联合：08 的插帧去模糊联合训练，互为正则化
- 要点：如果说第一层是"我们能做到"，第二层是"我们开始理解为什么能做到了"——网络开始有了决策机制。

**第三层：瓶颈突破（2024-2026）。**
- 无监督化：02（测试时自适应）、13（几何约束自监督）、17（相对坐标马尔可夫）、14（无监督在线）
- 多模态：16（事件相机融合）
- 物理建模回归：15（SO(3) 实时防抖）、14（经典 pipeline + 现代组件）
- 要点：这是你项目直接的学术上下文。你的工作是站在这一层上的。

**三层框架写到最后一小段做过渡：** 在梳理完这三层之后，自然引出你的方法定位——"本文在第三层的无监督化和在线化趋势下，结合门控时空注意力的特征选择机制，设计了一个..."

**可引用的论文：** 全部 17 篇可以按上述分层自然引用。不需要每篇都详细展开，参考文献里列全就行，文中引用那些对叙事推进重要的。

**写作注意事项：**
- 别写"某某人在某某论文中提出了某某方法"——太像翻译腔了。写成"GoPro 数据集的提出标志着视频去模糊进入了端到端时代[07]"，主语是方法本身。
- 每篇论文不要超过 2-3 句，重点是它和叙事线的关联，不是它的技术细节。
- 最后一层要写得比前两层更详细，因为这是你直接的学术邻居。

## 3. 方法（Methodology）

**篇幅：** 4-6 页。这是报告的核心，也是评分最重的部分。

**使用「00_技术选型」文档中的三阶段架构，展开成正式的方法描述。** 加上图（流程图 + 每模块的示意图）。

**3.1 总体架构**（0.5 页 + 一张流程图）

用一段文字 + 一张流程图描述整个三阶段流水线。解释为什么要模块化而非端到端（可控性、可解释性、组件可替换性——引用 LightStab 论文 14 作为架构思想来源）。

**3.2 运动估计模块**（1-1.5 页）

- 任务定义：输入两帧，输出帧间运动场
- 方案：稀疏关键点多检测器协作 + 因果光流融合（论文 14 路线）
- 为什么要用双检测器（SIFT + SuperPoint）：互补性，弱纹理场景的鲁棒性
- 为什么加因果光流融合：关键点只覆盖显著区域，稠密区域需要插值
- 如果简化了（比如只用 SIFT），如实写：在现阶段实验中采用 SIFT 作为单一检测器，多检测器协作留待后续优化（在结论中再次提及）。
- 公式：关键点匹配→RANSAC→仿射变换矩阵的一步步推导，写清楚。

**3.3 运动分解与平滑模块**（1.5-2 页）- **这是最有区分度的部分**

- 任务定义：从全局运动场中分离出相机抖动分量，保留物体运动分量，对抖动分量做时序平滑。
- 方案：仿射分解 + 相对坐标马尔可夫平滑（论文 09 + 论文 17 路线）
- 仿射分解：从运动场中拟合出全局仿射变换参数（平移、旋转、缩放、剪切），这 6 个参数代表相机的全局运动。残差自然就是物体运动。
- 相对坐标马尔可夫平滑：不直接平滑绝对坐标，而是建模帧间增量。在窗口半径 l=3 的马尔可夫约束下，对增量序列做高斯核平滑。窗口约束天然滤掉高频（=抖动），窗口重叠保持了长程平滑性。
- 为什么这个组合能区分抖动与运动：仿射分解把"全局的"和"局部的"分开，马尔可夫平滑再在时间轴上滤高频留低频。双重过滤。
- 公式：仿射矩阵的分解公式、增量和绝对坐标的关系、平滑核的数学形式。不需要多复杂，但要完整。
- 如果你用了简化的高斯滤波，也如实写，然后在对比实验中比较两者效果。

**3.4 帧合成与去模糊模块**（1 页）

- Warp 子模块：用平滑后的全局参数做仿射 warp，边界做反射填充 + 轻微裁剪。
- 去模糊子模块：简化版门控时空注意力（论文 12 简化），两帧输入 + 通道注意力自适应融合。解释为什么简化版对残留模糊够用。
- 如果需要，补充频域去模糊的思路（论文 16 启发），写在"可选增强"里。

**3.5 在线约束与效率分析**（0.5 页）

- 证明你的系统满足因果约束（不依赖未来帧）。
- 各模块的时间复杂度分析（光流计算 O(N²)、仿射拟合 O(N)、平滑 O(k)、warp O(N²)），做一张各模块运行时间占比的饼图或条形图。
- 如果代码还没跑通，先给理论复杂度，实验中补充实测时间。

**可引用的论文（按模块）：**
- 运动估计：14 (LightStab 多检测器)、10（光流防抖）
- 运动分解：09（GlobalFlowNet 仿射思路）、15（SO(3) 物理建模——可以在讨论中提到）
- 平滑：17（相对坐标马尔可夫）、11（多网格思想——如果用了多网格 warp）
- 去模糊：12（门控时空注意力）、08（联合训练思路——提到但不一定实现）、16（频域处理——未来工作）
- 边界处理：06（全帧输出策略）

## 4. 实验（Experiments）

**篇幅：** 4-5 页。60% 分数来自这里的效果展示。

**4.1 实验设置**（0.5 页）

- 测试素材：结课作业统一提供的标准测试视频（列出来源、分辨率、场景类型）
- 评估指标：PSNR、SSIM（帧间稳定性）、稳定比（Stabilization Ratio, SR）、运行时间（帧率 FPS 或每帧耗时 ms）
- 比较方法：如果实现了多个变体（比如高斯平滑 vs 马尔可夫平滑），做消融实验。用论文 07 作为 baseline（GoPro 原始网络在你的测试视频上的结果，或者用 OpenCV 的 ECC + 高斯滤波作为传统 baseline）
- 硬件环境：CPU/GPU 型号

**4.2 定量结果**（2 页）

- **主结果表**：一张表格，行是方法（baseline、你的简化版、你的完整版、如果有消融则每个变体），列是指标（PSNR、SSIM、SR、FPS）。这是评分最直接依据的那张表。
- **消融实验**：如果有多个变体（不同检测器数目、不同平滑策略），做消融表说明每个组件的贡献。
- **效率分析**：各模块运行时拆解。做一张饼图或表，展示运动估计 / 运动分解 / 平滑 / warp / 去模糊各占总运行时间的比例。
- 如果有些表的数据还没跑出来，就在对应位置标注"待测"，跑出来再填。

**4.3 定性结果**（1-1.5 页）

- **帧间稳定性可视化**：选一段典型的抖动序列（3-5 连续帧），展示原始帧 → 稳定帧的逐帧对比。排列成 2×N 的图（上排原始，下排稳定）。
- **运动轨迹图**：画原始相机的累积运动轨迹（随时间漂移的折线）和你的平滑后的轨迹（更平滑但保留了大趋势）。这是证明"保留了物体真实运动"最直观的方式。
- **失败案例**：不要只挑好的展示。挑一两个系统处理不好的场景（高速旋转、突然变焦、前景占据大半画面），分析原因。这比只展示成功案例更能体现你是真正理解了系统——老师知道没有任何方法是完美的，诚实面对失败案例反而加分。

**需要注意的是：** 这部分的很多内容依赖实际代码跑出来的结果。现在阶段可以先把上面这些框架写好，把该留的图表位置留出来，代码跑通后填入。

**可引用的论文（评估标准参考）：** 07（GoPro 数据集的评估范式）、14（LightStab 的消融实验设计）、06（盲估计的评估方法）。

## 5. 结论与展望（Conclusion）

**篇幅：** 0.5-1 页，三段。

**第一段：总结做了什么。** 一句话问题 + 一句话方法 + 一句话关键结果。

**第二段：局限性。** 诚实列 2-3 个当前方案的不足。比如：弱纹理场景依赖光流回退增加了计算量；极端运动（大范围快速旋转）下仿射分解可能失效；去模糊只处理了轻微残留模糊，对严重模糊能力有限。

**第三段：未来方向。** 从 limitations 自然延伸。可以从论文中找方向：
- 如果加了 IMU 传感器，可以用 SO(3) 物理建模替代仿射分解（引用 15）
- 在频域做去模糊可以降低计算量（引用 16）
- 移动端部署需要进一步的模型压缩和量化（引用 14 的轻量方向）
- 知识蒸馏可以将复杂光流网络压缩为小型网络（引用 09）

## 几个关键的写作原则

**不要写 AI 味的东西。** 就几件事会让你一眼被认出是 AI 写的：每段末尾用"总的来说"/"综上所述"收束；连续多段用"首先...其次...最后..."结构；开头总是"随着深度学习的快速发展..."；遇到任何问题都"具有重要意义"。这些全删掉。用你自己的语言写——你可以先写成口语化的草稿，再把长句子拆短，最后调整措辞让它看起来像论文语言但不过度正式。

**明确引用。** 每个技术选择、每个性能数值、每个架构决策，后面都挂上引用。不要让你的论文看起来像是在"凭空想出来的"。老师要看到你读了论文、理解了论文、并且能用论文支撑自己的设计决策。

**公式和图是你的朋友。** 方法部分至少要有 3-5 个公式（运动估计的仿射参数化、平滑的目标函数、去模糊的频域操作），至少 3 张图（总体架构流程图、轨迹对比图、帧间效果图）。公式和图是"认真做了"的最直观证据。

**对比是说服力的来源。** 只展示自己的结果是不够的。要有 baseline 对比（哪怕是简单 baseline）、消融实验（证明每个组件的作用）、失败案例分析（展示理解深度）。

## 如果要开始写代码

推荐顺序（和「00_技术选型」里的两轮计划一致）：

1. **运动估计**：装 OpenCV，调 `cv2.findTransformECC` 或手写 RANSAC + SIFT 匹配，验证能跑通
2. **仿射分解 + 高斯平滑**：最简单的版本，先拿到一个稳定但可能不够好的结果
3. **相对坐标马尔可夫平滑**：替换高斯平滑，这是你的方法最大的区分点
4. **去模糊后处理**：warp 后如果效果还行就跳过；如果有残留模糊再加
5. **多检测器协作**：最后的锦上添花

代码仓库建议放在 GitHub 上（哪怕私有仓库），README 里写清楚环境配置和运行步骤。结课答辩时当场跑一遍给老师看，比任何 PPT 都有说服力。
